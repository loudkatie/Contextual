# TestFlight Deployment Guide

This guide walks through how to prepare, build, and distribute the Contextual iOS app through
TestFlight. Loud Labs follows a predictable release flow so anyone on the team can safely ship a new
build.

---

## 1. Requirements

Before submitting any build:

- Xcode (latest stable version)
- Apple Developer account with access to the Loud Labs team
- App Store Connect permissions (Developer or App Manager)
- The correct bundle identifiers set in Xcode

If you’re missing access, notify the team and an admin will enable TestFlight permissions.

---

## 2. Build preparation

1. Open the project at:

   ```
   ~/04_Developer/Contextual/ios/ContextualApp/Contextual.xcodeproj
   ```

2. In Xcode:
   - Select **Any iOS Device (arm64)** from the device dropdown.
   - Go to **Signing & Capabilities**.
   - Confirm:
     - Team: *Loud Labs*
     - Bundle ID: `com.loudlabs.Contextual`
     - Provisioning Profile: automatic ( generated by Xcode )

3. Increment the version numbers:
   - **Version** (marketing version): update when major features land.
   - **Build**: increment for every TestFlight upload (`1`, `2`, `3`, …).

---

## 3. Archive & upload

1. In Xcode:
   - `Product` → `Archive`.
   - Wait for the archive window to open.
2. Select the most recent build.
3. Click **Distribute App**.
4. Choose **App Store Connect** → **Upload**.
5. Ensure:
   - “Include bitcode” = *disabled*.
   - “Rebuild from bitcode” = *disabled*.
   - “Upload symbols” = *enabled*.

6. Click **Upload**.

Xcode will push the build to App Store Connect. This usually takes 2–10 minutes.

---

## 4. TestFlight configuration

1. Log in at <https://appstoreconnect.apple.com>.
2. Pick the **Contextual** app.
3. Navigate to **TestFlight**.
4. Find the uploaded build (may show “Processing” for several minutes).
5. Once processing completes:
   - Add release notes (what changed).
   - Enable **Internal Testing** for teammates.
   - Add yourself and others to the tester list.

---

## 5. Publishing to external testers (optional)

Apple requires a brief review for external TestFlight builds.

To submit:

1. Go to **TestFlight → External Testing**.
2. Create a **New Group**.
3. Add testers via email or public link.
4. Submit the build for review.

Apple typically approves TestFlight builds within 30 minutes–6 hours.

---

## 6. After publishing

Every time a build goes out:

- Announce in Slack / Notion with:
  - Build number
  - Key changes
  - Known issues (if any)
  - Call for testing

- Update the changelog in:
  ```
  docs/operations/changelog.md
  ```

---

## 7. Troubleshooting

**Build not appearing in TestFlight**
- Wait 5–10 minutes; Apple’s processing queue can be slow.
- Confirm your bundle identifier is correct.
- Make sure the build uses `Any iOS Device (arm64)`.

**Signing errors**
- Delete derived data:
  ```
  rm -rf ~/Library/Developer/Xcode/DerivedData
  ```
- Reopen Xcode and try again.

**Archive option is disabled**
- Ensure no simulator device is selected.
- Choose “Any iOS Device (arm64).”
